### 🏥 [Healix-AI](https://github.com/Nijjil-Narula/Healix-AI)

> **Privacy-preserving clinical diagnostic assistant** — a stateless RAG platform coupling **Groq LLaMA 3.3-70b-versatile** with a Pinecone vector index to deliver grounded, evidence-based medical answers from a validated clinical corpus.

| | |
|---|---|
| **LLM & Embeddings** | Groq `LLaMA 3.3-70b-versatile` · HuggingFace `sentence-transformers/all-MiniLM-L6-v2` (384-dim cosine) |
| **RAG Stack** | LangChain · Pinecone Serverless (`healthwise-chatbot` index, AWS `us-east-1`) · `RecursiveCharacterTextSplitter` (chunk=500, overlap=20) · `pypdf` for PDF ingestion |
| **Backend Architecture** | **Stateless Flask API** — zero server-side session storage; conversation history transferred via client payload and hydrated into `HumanMessage`/`AIMessage` objects via `MessagesPlaceholder` |
| **Frontend** | Tailwind CSS dark UI (`zinc-950` backdrop, tech-green accents) · HTML5 `localStorage` consultation vault · Triage suggestion chips (Hypertension, Cold vs. Flu, Vaccines, Migraines) |
| **Guardrails** | Hallucination guard: if context does not contain the answer, returns a fixed fallback message — no guessing or free-form generation |
| **Deployment** | Docker · **AWS EC2** (served on `:8080`) · **AWS ECR** image registry · **GitHub Actions CI/CD** (build → push to ECR → deploy to EC2 on every `main` push) |

### 🚨 [Incident Copilot](https://github.com/Nijjil-Narula/incident-copilot)

> **Production-grade DevOps incident response & post-mortem copilot** — a FastAPI + Streamlit system with a four-layer grounded post-mortem engine, SHA-256 Redis answer cache, strict command-safety guardrails, and LangSmith tracing.

| | |
|---|---|
| **LLM & Embeddings** | Google `Gemini 3.5 Flash` · HuggingFace `all-MiniLM-L6-v2` for in-process FAISS indexing |
| **Backend & API** | **FastAPI** (async lifespan, PostgreSQL via SQLAlchemy async sessions) · Routers: `/incidents`, `/knowledge`, `/health` · Full Swagger/OpenAPI at `:8000/docs` |
| **RAG Knowledge Base** | In-process **FAISS** vector store · section-aware chunking of `.md`/`.txt`/`.pdf` runbooks · KB version tracking with automatic cache invalidation on document ingest |
| **Caching & Concurrency** | **Redis** single-flight cache with SHA-256 keys (`kb_version` + model ID + prompt version + normalized question) · in-memory lock + 30-second circuit breaker |
| **Safety Guardrails** | Whole-command verification pipeline: shell commands extracted from runbook chunks, normalized and matched exactly against retrieved runbooks; unverified commands auto-redacted to `[UNVERIFIED COMMAND REMOVED]`; destructive commands (`rm -rf`, `DROP DATABASE`, `fdisk`) flagged with visual caution badges |
| **Post-Mortem Engine** | 4-layer report: (1) Incident header table (2) 6-heading grounded LLM sections with one-time auto-retry (3) Deterministic chronological timeline (≤60 rows) (4) Audit footer with safety redaction metrics |
| **Observability** | **LangSmith** tracing (`@traceable` decorators on all LLM calls, tagged with `kb_version`, model, guardrail outcome) |
| **Deployment** | **Docker Compose** (FastAPI `:8000` + Streamlit `:8501` + PostgreSQL `:5432` + Redis `:6379`) · Pytest integration test suite + 14-point guardrail self-test suite |
